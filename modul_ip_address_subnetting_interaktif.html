01 / Fondasi

Mengapa IP address diperlukan?

Alamat logis pada lapisan jaringan untuk pengiriman paket antarjaringan; bukan identitas orang atau perangkat yang selalu permanen.

Model komunikasi yang dipakai

Internet Protocol (IP) memuat informasi alamat sumber dan tujuan paket pada lapisan jaringan. Router memakai tabel routing untuk memilih langkah berikutnya. Berbeda dari MAC address yang bekerja pada lingkup tautan lokal, alamat IP dapat dipakai untuk mengarahkan lalu lintas antarjaringan. DNS memetakan nama domain ke alamat dan default gateway merupakan next-hop untuk tujuan di luar jaringan lokal. [R1][R2]

Skema konseptual: gateway dipakai jika jaringan tujuan berada di luar prefix yang diketahui sebagai on-link oleh host.

IPv4

Alamat 32 bit, ditulis sebagai empat oktet desimal (0–255) dengan titik.

192.168.10.130

Jumlah kombinasi biner: 232 ≈ 4,29 miliar, tetapi tidak semuanya dapat digunakan sebagai alamat unicast publik.

IPv6

Alamat 128 bit, ditulis dalam delapan kelompok heksadesimal, dan dapat disingkat menurut aturan tertentu.

2001:db8:abcd::1

Jumlah teoritis: 2128 kombinasi. Tidak memiliki mekanisme broadcast seperti IPv4. [R7][R8]

Empat konsep yang sering tertukar

Alamat IPIdentitas logis interface untuk komunikasi IP; satu perangkat dapat memiliki lebih dari satu alamat.
Prefix / subnet maskPenanda bagian bit jaringan yang digunakan dalam pencocokan prefix.
SubnetBlok alamat yang berbagi prefix jaringan yang sama.
Default gatewayRouter tujuan awal untuk paket ke luar jaringan lokal; bukan alamat broadcast.
Catatan akademikIP tidak menjamin pengiriman paket sampai ke tujuan, keterurutan, ataupun reliabilitas end-to-end. Kinerja tersebut memerlukan mekanisme/protokol lain jika dibutuhkan. Alamat IP juga tidak sama dengan alamat fisik perangkat.
02 / Matematika jaringan

Biner, oktet & operasi bit

Subnetting pada dasarnya adalah proses mengatur bit, bukan menghafal daftar angka.

Dari desimal ke biner

Setiap oktet IPv4 memiliki 8 posisi bernilai 128, 64, 32, 16, 8, 4, 2, 1. Pilih bit 1 pada nilai yang dijumlahkan, sisanya 0.

Posisi1286432168421
Contoh 13010000010
130 = 128 + 2 = 10000010₂

Logika AND untuk network address

Operasi AND bernilai 1 hanya jika kedua bit bernilai 1. Network = IPv4 AND subnet mask. Bagian host pada mask berisi nol, sehingga bit host pada network address selalu nol.

IP 192.168.10.130 = 11000000.10101000.00001010.10000010
Mask 255.255.255.192 = 11111111.11111111.11111111.11000000
AND = 11000000.10101000.00001010.10000000
Network = 192.168.10.128

Dalam IPv4, broadcast sebuah subnet konvensional diperoleh dengan mengatur semua bit host menjadi 1. Contoh 192.168.10.128/26 mempunyai broadcast 192.168.10.191.

03 / Klasifikasi alamat

Alamat yang tampak mirip belum tentu mempunyai penggunaan dan kebijakan routing yang sama.

Kelas A/B/C: sejarah, bukan aturan subnetting modern

Pengalamatan awal IPv4 mengenal kelas A (mask bawaan /8), B (/16), dan C (/24), serta D untuk multicast. Model classful ini tidak lagi menjadi dasar penentuan ukuran blok dalam perencanaan modern. CIDR menggunakan prefix eksplisit, misalnya 10.4.2.0/23 tanpa bergantung pada kelas alamat. [R1][R2]

Kesalahan umumAngka pertama 192 tidak otomatis berarti /24. Selalu baca panjang prefix atau subnet mask yang diberikan.
04 / CIDR

Subnet mask & prefix length

Notasi /n menunjukkan berapa banyak bit paling kiri yang dipakai sebagai prefix jaringan.

Eksplorasi 32 bit: geser panjang prefix

Warna biru = bit jaringan; hijau = bit host. Semua bit mask harus berupa deretan 1 di kiri kemudian 0 di kanan (kontigu).

Prefix yang dipilih/26—
Network bitsHost bits

Rumus dasar & keterbatasannya

Host bits = 32 − n
Total alamat = 2^(32 − n)
Host usable (subnet konvensional /0–/30) = 2^(32 − n) − 2

Rumus host usable hanya berlaku untuk subnet IPv4 konvensional. Pada /31, dua alamat dapat dipakai sebagai endpoint pada link point-to-point yang sesuai RFC 3021; tidak menggunakan broadcast biasa. Pada /32, hanya ada satu alamat tunggal (host route), bukan jaringan multi-host. Jangan terapkan “minus dua” secara mekanis pada keduanya. [R2][R4]

Pencocokan prefix & longest-prefix match

Dalam routing modern, router dapat memiliki beberapa rute yang cocok dengan alamat tujuan. Pada kondisi kebijakan routing yang lazim, rute dengan prefix paling spesifik (panjang terbesar) dipilih; misalnya tujuan 10.20.5.9 cocok dengan 10.0.0.0/8 dan 10.20.5.0/24, sehingga /24 lebih spesifik.

Subnetting membagi blok menjadi subnet lebih kecil; route summarization menggabungkan prefix berurutan yang memenuhi batas biner menjadi rute agregat. Agregasi tidak boleh dilakukan asal rentang numeriknya berdekatan.
05 / FLSM & perhitungan

Menghitung subnet IPv4

Gunakan prosedur sistematis, cek network alignment, lalu validasi dengan kalkulator bawaan.

Contoh lengkap: 192.168.10.130/26

1
Identifikasi host bits

Prefix /26 menyisakan 32 − 26 = 6 bit host.

2
Hitung jumlah alamat

2^6 = 64 alamat per subnet; host konvensional 64 − 2 = 62.

3
Cari kelipatan blok

Oktet terakhir memiliki ukuran blok 256 − 192 = 64. Titik awalnya 0, 64, 128, 192. Alamat .130 berada dalam blok .128–.191.

4
Tentukan empat nilai penting

Network 192.168.10.128; first host 192.168.10.129; last host 192.168.10.190; broadcast 192.168.10.191.

Subnet /26 dalam 192.168.10.0/24Host pertamaHost terakhirBroadcast

Subnet calculator

Interaktif • IPv4

Masukkan alamat IPv4, beserta prefix CIDR /n atau subnet mask dalam format dotted decimal. Kalkulator juga menangani /31 dan /32.

Apakah dua alamat berada pada subnet yang sama?

Perbandingan valid bila prefix/mask yang diterapkan ke kedua alamat sama. Perhatikan bahwa komunikasi nyata juga bergantung pada tabel routing, VLAN, dan konfigurasi tautan.

Catatan /31 dan /32Dalam kalkulator, kolom broadcast pada /31 ditandai “tidak dipakai sebagai broadcast biasa”; kedua alamat dapat digunakan hanya pada konteks point-to-point yang sesuai. /32 merepresentasikan satu alamat dan tidak memiliki rentang host normal. Jangan menafsirkan jumlah alamat teoretis sebagai jumlah perangkat yang selalu dapat dihubungkan.
06 / Perencanaan alamat

FLSM vs VLSM

Rencanakan subnet berdasarkan kebutuhan, bukan semata mengikuti kebiasaan mask /24.

FLSM

Fixed Length Subnet Mask

Semua subnet mempunyai ukuran/prefix yang sama. Sederhana dikelola tetapi berpotensi menyisakan banyak alamat tidak terpakai jika kebutuhan host sangat bervariasi.

Contoh: 192.168.10.0/24 dibagi empat subnet /26, masing-masing 64 alamat (62 host normal).

VLSM

Variable Length Subnet Mask

Subnet berbeda boleh memakai prefix berbeda sesuai kebutuhan. Dialokasikan dari terbesar ke terkecil dengan mempertahankan batas blok biner dan mencegah overlap.

Contoh: 60 host → /26; 28 host → /27; 12 host → /28; 2 host → /30 (jaringan biasa).

Algoritma merancang VLSM dengan benar

  1. Catat jumlah perangkat, interface gateway, kemungkinan ekspansi, dan segmen terpisah.
  2. Untuk setiap kebutuhan host H, cari h terkecil sehingga 2^h − 2 ≥ H untuk subnet biasa. Prefix = 32 − h.
  3. Urutkan subnet dari kebutuhan alamat terbesar ke terkecil.
  4. Alokasikan setiap subnet pada alamat awal yang sesuai kelipatan ukuran blok (alignment).
  5. Pastikan semuanya berada di dalam blok induk, tidak overlap, dan catat gateway serta cadangan.
  6. Verifikasi kembali network, broadcast, rentang host, dan kebutuhan peran interface.
Pertimbangan praktisMemilih prefix yang tepat bukan hanya soal minimisasi sisa alamat. Perencanaan harus mempertimbangkan pertumbuhan, konsistensi rute, batas organisasi, VLAN, dan persyaratan keamanan. Lihat [R2][R10].

VLSM Planner: rancang sendiri

Simulasi otomatis

Setiap baris ditulis dengan format Nama Segmen, Jumlah host. Kebutuhan host sudah termasuk gateway jika interface gateway membutuhkan satu alamat di subnet itu. Planner memakai subnet konvensional, bukan /31.

Pengantar route summarization

Misalnya 192.168.20.0/24 dan 192.168.21.0/24 dapat dinyatakan sebagai 192.168.20.0/23 karena berurutan dan batas /23 sesuai. Sebaliknya 192.168.21.0/24 dan 192.168.22.0/24 tidak dapat disatukan tepat hanya menjadi satu prefix /23 tanpa mencakup jaringan lain.

07 / Jaringan masa kini

IPv6 dan subnetting modern

IPv6 mempertahankan ide prefix tetapi berbeda dalam representasi, autokonfigurasi, dan perilaku tetangga.

Format IPv6

Delapan kelompok heksadesimal (masing-masing 16 bit) menghasilkan 128 bit. Nol di awal kelompok dapat dihilangkan. Satu rangkaian kelompok nol terpanjang dapat diganti ::, dan penyingkatan :: maksimal satu kali per alamat. Untuk representasi kanonis, lihat RFC 5952. [R7][R8][R9]

Panjang: 2001:0db8:0000:0000:0000:0000:0000:0001
Singkat: 2001:db8::1
Prefix: 2001:db8:1234:10::/64

Prefix 2001:db8::/32 dicadangkan untuk dokumentasi, bukan digunakan di jaringan produksi. Contoh di modul menggunakan prefix dokumentasi.

Jenis alamat IPv6

Jenis / prefixFungsi

::/128Unspecified address.
fe80::/10Link-local, digunakan pada satu link.
fc00::/7Unique Local Address (ULA), umumnya fd... untuk alokasi lokal.
ff00::/8Multicast; IPv6 tidak menggunakan broadcast seperti IPv4.
Global unicastAlamat unicast global dari blok yang dialokasikan untuk tujuan tersebut; jangan simpulkan dari sekadar “bukan ULA”.

LAN IPv6 sering memakai prefix /64, terutama untuk SLAAC, tetapi tidak berarti semua prefix IPv6 wajib /64 dalam setiap konteks. Penentuan apakah alamat tujuan berada “on-link” tidak boleh hanya disimpulkan dari pemberian alamat interface. [R8][R11]

08 / Studi kasus

Desain jaringan laboratorium kampus

Hubungkan perhitungan matematis dengan keputusan desain yang dapat dipertanggungjawabkan.

Skenario

Unit TIK memperoleh blok 192.168.50.0/24 untuk empat segmen yang terpisah secara logis. Kebutuhan alamat adalah Lab 1: 70 host, Lab 2: 40 host, Administrasi: 20 host, dan Ruang server: 10 host. Kebutuhan sudah termasuk interface gateway masing-masing. Rancang VLSM tanpa overlap.

09 / Praktikum terbimbing

Eksperimen & laporan praktikum

Praktik virtual dapat dilakukan tanpa router fisik; aktivitas konfigurasi nyata bersifat opsional.

Eksperimen A • Membuktikan AND dan batas subnet

  1. Di kalkulator, uji 192.168.10.130/26 dan catat network/host/broadcast.
  2. Ubah hanya alamat IP menjadi 192.168.10.191; tentukan apakah bisa dipakai sebagai host biasa.
  3. Ubah prefix menjadi /25; bandingkan network, broadcast, dan banyak host.
  4. Jelaskan alasan perubahan menggunakan minimal satu baris biner.
Hasil yang diharapkanPada /26, .191 adalah broadcast blok .128/26, bukan host biasa. Pada /25, .130 berada di jaringan .128/25 dan broadcast-nya .255.

Eksperimen B • Menguji dua perangkat

  1. Periksa 192.168.10.62 vs 192.168.10.65 dengan /26.
  2. Ulangi dengan /25, lalu /24. Catat kapan keduanya berada dalam prefix yang sama.
  3. Diskusikan perbedaan “berada dalam subnet yang sama” dan “dapat saling ping”.
Kunci konsep/26: berbeda (.0 dan .64); /25: sama (.0/25); /24: sama (.0/24). Ping dapat gagal karena firewall, routing, VLAN, host offline, atau ICMP diblokir.

Eksperimen C • Desain dan argumentasi VLSM

  1. Uji skenario studi kasus kampus di VLSM Planner dengan 192.168.50.0/24 dan Lab 1,70; Lab 2,40; Administrasi,20; Server,10 (satu baris per segmen).
  2. Rekam tabel hasil serta jumlah alamat sisa, lalu coba menaikkan kebutuhan Lab 1 dari 70 menjadi 130.
  3. Tulis kesimpulan: apakah blok induk masih cukup? Berikan alternatif desain dan alasannya.
Pembahasan70 → /25, 40 → /26, 20 → /27, 10 → /28 muat di /24. Jika Lab 1 menjadi 130, diperlukan /24 (254 host), sehingga bersama segmen lain tidak dapat semuanya ditampung dalam satu /24.

Dua komputer memiliki alamat 192.168.7.30/27 dan 192.168.7.33/27. Apakah mereka berada dalam subnet yang sama? Buktikan memakai rentang blok dan jelaskan implikasi routing.

10. Rancangan VLSM dan risiko ekspansi (10 poin)

Institusi memiliki 10.10.0.0/24, dengan segmen 90, 35, 20, dan 8 host (sudah termasuk gateway). Tentukan alokasi subnet yang valid dan jelaskan satu risiko desain.

Rubrik dan pembahasan esai untuk dosen / belajar mandiri

Esai 9: subnet 192.168.7.0/27 mencakup .0–.31 (usable .1–.30), sementara 192.168.7.32/27 mencakup .32–.63 (usable .33–.62). Jadi berbeda subnet. Perlu forwarding melalui router jika ingin berkomunikasi secara IP secara normal. Rubrik 10: (4) kedua network benar, (3) rentang valid, (3) implikasi routing relevan.

Esai 10, contoh alokasi valid: 90 → 10.10.0.0/25 (usable .1–.126); 35 → 10.10.0.128/26 (.129–.190); 20 → 10.10.0.192/27 (.193–.222); 8 → 10.10.0.224/28 (.225–.238), sisa .240–.255. Rubrik 10: (4) prefix sesuai, (4) tidak overlap dan dalam blok, (2) diskusi pertumbuhan/operasional.

Catatan metodologis

Definisi teknis dan pengecualian mengutamakan standar RFC sebagai sumber normatif. Bahan perguruan tinggi digunakan sebagai inspirasi cakupan pembelajaran. Nilai host yang ditampilkan kalkulator adalah estimasi usable pada subnet IPv4 konvensional; kebutuhan nyata bisa berbeda menurut fitur perangkat dan topologi. Contoh pengalamatan internal memakai blok RFC 1918, sedangkan ilustrasi IPv6 memakai 2001:db8::/32.

Modul disusun untuk kegiatan akademik. Pengguna tetap perlu memeriksa pembaruan standar saat melakukan implementasi jaringan produksi.
